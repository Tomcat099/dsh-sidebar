# dsh-sidebar

把 DSH 左侧导航改成三段：功能菜单、项目对话树、快速对话的最近记录。工作区的折叠、高亮、重命名和删除仍由 DSH 自己渲染。底部「设置」不变。

四个配置页是本插件自己的主区骨架，字段会在后续迭代里补上。「新对话」始终打开同一个后台项目，项目树里不显示它，会话只出现在「最近对话」。

搜索框留在「项目」标题旁。DSH 没有单独的搜索槽，不能把它挪到 Logo 右侧。宿主如果本来就不画出空项目，这里也不会补一行「暂无对话」。

## 记忆

跨会话记住偏好、约定与项目事实。默认全自动：一轮对话安静下来后用当前模型提炼事实入库，下一轮按用户输入召回并注入到系统提示的运行时上下文里；Agent 也可以主动调用三个工具。

- 存储：默认本地 SQLite（Node 自带的 `node:sqlite`，无原生依赖），库文件在 `~/.dsh/dsh-sidebar/memory/memory.sqlite`；也可以在配置里切到外部服务（Mem0 风格 HTTP REST，或 MCP）。外部 MCP 不需要填工具名：连接时通过 `tools/list` 自动识别检索/写入工具，已挂载的 streamable-http 服务还能在下拉里直接选。
- 检索：FTS5 全文 + `LIKE` 兜底 + 向量余弦三路并行，默认用 RRF 融合；向量需要一个 OpenAI 兼容的 `/embeddings` 接口，未配置时自动退化为纯关键词检索。
- 维度：配置里的「维度」会作为 OpenAI `dimensions` 字段发给接口（多数服务按此截断）；如果服务忽略它、返回了别的长度，就以实际长度为准并把实际值回写到配置，保持两边一致——不会因为维度填错就整轮失败。界面会显示 `维度 1536 → 1024` 这种对齐结果，换过维度后用「重建向量」刷新旧行。
- 注入分两层：一层是「用户长期偏好」（`preference` / `convention` 类记忆，最多 20 条、1200 字），跟当前问题无关、**任何会话的第一轮就在上下文里**；一层是「相关记忆」，按当前会话最近一条用户输入检索（2000 字内）。之所以要恒定注入那一层：一轮的系统提示在用户消息到达的瞬间就组装完了，异步检索根本来不及，新会话第一问必然召回不到。
- 工具：`memory_search`、`memory_write`、`memory_forget`。
- 提炼规则（决定「什么才算值得记」）：`提炼模式`（每轮自动 / 仅明确要求，后者只在你说「记住…」时才提炼）、`触发词`、`提炼来源`（默认只读用户发言，助手发言容易带出推测）、`允许类型`、`置信度下限`（默认 0.7，低于即丢）、`单轮上限`（默认 5）、`额外关注` / `额外排除`（自然语言，直接拼进提炼提示词）。默认已收紧：只读用户发言、≥0.7 置信度、单轮最多 5 条，并明确禁止记录寒暄、临时状态、可从文件重读的内容、对话过程本身与助手自身的元陈述。嫌吵就把模式切成「仅明确要求」。
- 去重：记忆身份按「抹掉标点、空白、全角差异后的文本」计算，所以「用户喜欢喝霸王茶姬。」和「用户喜欢喝霸王茶姬」是同一条；写入时还会对向量做 0.985 余弦的近重复合并（同义改写）。老库升级到 schema v2 时自动重算历史哈希并合并已有重复行，工具箱「记忆」页也有「合并重复」按钮手动触发。
- 触发：会话事件是快路径，另有 5 秒一次的活跃会话扫描兜底（读 `ctx.agents` 里根 agent 自己的日志），所以即使事件没送到插件也能提炼；一轮对话结束后约 8 秒写入。
- 界面：`设置 → 插件 → 插件配置 → 记忆`（卡片可收缩）管存储方式、嵌入、开关与召回条数；侧边栏 `工具箱 → 记忆` 用来搜索、增删改，并显示「会话事件 / 轮询 / 最近提炼」诊断，提炼失败会直接把错误显示出来。
- 提炼走 `ctx.llm.stream`，两个坑：`purpose` 是封闭联合（只允许 `compaction` / `session-title`），辅助调用必须留空；`llm` / `agents` 是隔离服务，直接 `ctx.llm` 会抛 `cannot get property "llm" without inject`，必须在 `ctx.inject(['llm'], scoped => …)` 里取。

配置存在 `~/.dsh/settings.yaml` 的 `dsh-sidebar-memory:` 段里。设置卡片由宿主 `settings.installSection` 与浏览器半边注册的 `settings.plugin.item` 卡片配对生效，缺任一边都不会显示。

## MCP

「工具箱 → MCP」是一份列表，按作用域切换。保存后立即重新挂载 `@deepseek-ai/dsh-mcp-client`，不需要重启。

**配置存在哪**

- `全局`：`~/.dsh/profiles/<profile>/.mcp-servers.json`，对所有工作区生效。
- `工作区`：`<项目根>/.dsh/.mcp-servers.json`。项目根按 `.git` 向上找，和技能的判定一致；同一个仓库下的多个工作区共用同一份。
- 作用域选择和技能页同一个形状：先点「全局 / 工作区」，选工作区时再列出具体是哪一个——不会默默对「当前打开的项目」下手。
- 同名条目以工作区级为准（工作区覆盖全局），两条同名条目不会同时挂载。
- 切换作用域或工作区时如果还有未保存的改动，会先确认再切。
- 每次保存都会写 `revision`，保存时带上它做乐观并发校验；期间被别处改过会拒绝写入并提示刷新，而不是覆盖。

**保存前会真的连一次**

保存前会挑出改动过的条目握手一次（`initialize` + `notifications/initialized` + `tools/list`），并按「改了什么」分两档：

- **改了指到哪里**（新增条目，或 `transport` / `url` / `command` / `args` / `cwd` 变了）：握手失败就**不写入**。一个错的地址不是等一等就会好的东西。想强行存下来用「跳过握手保存」。
- **只改了怎么鉴权或设置**（`headers` / `headerEnv` / `env` / `envEnv` / `toolsets` / `readonly`，以及重新启用）：握手失败只**警告**，配置照常保存。

第二档之所以不阻断，是因为换 token 时要求新 token 立刻可用是说不通的；迁移凭据之后变量要重启才进进程环境，卡在那里就是个死循环。而健康检查几秒后就会把那行标红，那才是它该被看见的地方。

没改过的条目不会被重复探测。

`stdio` 条目不在这里探测——那个进程由 DSH 启动。它的状态只在 Host 能汇报工具注册情况时才判定，否则显示「状态未知」，不会冒充健康。

**诊断**

连接状态是 8 态：`未配置 / 状态未知 / 已停用 / 已连接 / 部分异常 / 需重新授权 / 自动重试中 / 连接异常`。每条失败都会给出失败阶段（配置 / 鉴权 / 网络与传输 / MCP 初始化 / Host 启动 / Host 状态观测 / 工具发现 / 可用性确认）、稳定错误码和建议动作。

行上直接显示「失败阶段 · 原因」；展开那一行会看到完整句子和「建议：…」。稳定错误码、检查时间、上次成功时间、工具数、下次重试时间仍在 `/health` 的返回里，只是不在页面上铺开——一切正常时不该再堆一段话解释它有多正常。

健康结论 5 分钟过期，后台每 30 秒检查一次到期项。失败按 30s→60s→2min→5min 退避；**鉴权失败会暂停自动重试**，因为重试一个被拒的 token 不会成功，还可能触发锁定。首次打开页面先渲染已有结论，再在后台补一次真实握手，不会卡在超时上。

错误分类覆盖：`auth`、`authorization-required`（引用的环境变量为空）、`rate-limit`（读 `Retry-After`）、`dns`、`tls`、`refused`、`timeout`、`network`、`http`、`protocol`、`tool-list`，以及 stdio 的 `startup` / `process-not-found` / `process-exit`。

**工具发现**

工具清单跟着服务器走：点开某一行就是那一条的工具列表，点某个工具看参数结构与模型侧名称，右上角的「重新发现工具」重新拉一次。结果带时间戳缓存在 `~/.dsh/profiles/<profile>/.mcp-cache/tools.json`。缓存里的 `inputSchema` 在写入前就会裁剪（深度 6、每层 60 个属性、描述 600 字），避免远端塞一个渲染不动的 schema 进页面。缓存的含义是「上次成功拿到的清单」，不等于服务当前可调用。

本地进程（`stdio`）由 Host 启动，这个进程既调不到也列不出它的工具，所以那一行会明说做不到，而不是报一个假的失败。

**导入 / 导出**

导入认 `{ "mcpServers": { ... } }`，也认 `servers` / `connections` / 裸数组；`transport`、`type`、或只有 `command` 都能推断传输方式，`sse` 归一成 `streamable-http`。整份内容先整体校验，有一条不合法就整体拒绝。同名冲突可以选覆盖 / 跳过 / 自动加后缀。

导出是脱敏的：静态 header 与 env 字面值、本地目录、URL 的查询参数都会替换成占位符；**环境变量名会保留**，否则导出没法在别的机器上导入。凭据、`~/.dsh/.env` 的内容永远不会出现在导出、快照或页面里。

**备份**

每次保存前自动留一份，最多 20 份，超出时优先淘汰自动备份、保住手动备份。第一份内容为空的作用域不留快照，免得把真正的备份挤出上限。页面不再提供备份子页，但 `/mcp-settings/snapshots*`（`list` / `create` / `preview` / `restore` / `delete`）仍然可用，恢复前会先给预览。

**作用域互转**

全局和项目之间的复制 / 移动会先预览再提交。凭据不跟着搬：条目保留原来的 `headerEnv` / `envEnv` 变量名，接收方依赖同一批环境变量。

**凭据迁移**

`headers` / `env` 里的明文凭据**既不影响使用，也不会出现在校验结果里**。校验只报真正会挡住保存的问题；凭据整理是一个独立入口，放在工具栏的「迁移明文凭据」上，需要时再点。

理由：这个文件是本地连接记录，按 `0600` 写，和它要把值搬去的 `.env` 同级；真正会离开本机的只有导出，而导出已经脱敏。所以把凭据写在这里是正常的，不该在每次保存时提醒一次。

点开会先列方案（变量名、新增还是覆盖、值的字符数——**不含值本身**），确认后写入 `<DSH_HOME>/.env` 并把条目改成环境变量引用；也可以完全不理它。

- 能自动搬的：`Authorization: Bearer <token>` → `headerEnv.Authorization`（值为裸 token，挂载时由渲染器补回 `Bearer `）；stdio 的 `env` 字面值 → `envEnv`。
- 不会自动搬的：非 Bearer 形式的 header、URL 查询参数、命令参数里的凭据——会把原因列出来让你手动改，而不是猜。
- 写 `.env` 时会拒绝 `DSH_` / `XDG_` / `DYLD_` / `BASH_FUNC_` 前缀和一批引导变量（如 `PATH`、`NODE_OPTIONS`、`HTTP_PROXY`）：DSH 启动时遇到这些名字会直接抛错，写进去等于让 `dsh web` 起不来。含空格、引号、`$`、`#` 的值也会被拒，因为没法保证转义正确。
- 文件以 `0600` 写入，注释、顺序和其他行原样保留。
- **DSH 只在启动时读这个文件**，所以迁移完要重启 `dsh web` 才生效；在那之前对应的行会显示「需重新授权」并说明原因。

**安全边界**

- URL 只允许 `https://`；明文 `http://` 只放行回环地址（`127.0.0.1` / `localhost` / `::1`）。
- `10./172.16-31./192.168.` 与 IPv6 ULA 字面量需要显式打开「允许明文访问内网」——默认的「仅 HTTPS」已经能覆盖大多数内网 MCP。
- 域名和公网地址一律不允许明文 HTTP；链路本地与云元数据地址（`169.254.169.254` 等）永远拒绝，确认开关也不能放行。
- 响应体上限 2 MiB（先看 `content-length`，再边读边判，超限即中断），浏览器请求体上限 1 MiB。
- 静态 header / env 里的明文凭据不算问题（本地记录、`0600`、导出脱敏）；想整理可以点工具栏的「迁移明文凭据」搬进 `~/.dsh/.env`。命令参数和 URL 查询参数里的凭据不会被自动搬移，因为长参数未必是密钥。
- 配置文件和快照按 `0600` 写，目录 `0700`。

**页面行为**

- 行上只放状态：名称、状态点、「失败阶段 · 原因」、状态标签、启停开关、编辑、删除。
- **点行是展开，展开看的是这一条的工具清单**，不是配置。改配置走右侧的铅笔按钮——两件事分开，就不会出现「想看一眼工具有什么，结果弹出一个表单」。
- **配置信息只在编辑弹窗里**，和「+ 添加 MCP」同一个弹窗、同一套字段，不存在只在一边能改的东西。弹窗中部可滚动，字段再多也不会把底部的「保存」挤出可视区。
- 列表里只有一个新增入口：「+ 添加 MCP」。嵌在工具箱里时面板不再重复放一个「添加」。
- 保存因为握手被拒时，失败的那一条会**自动打开编辑弹窗**，原因留在那一行的副标题上。

- 出问题的那一行副标题直接写「失败阶段 · 原因」，不用点开才知道为什么红；完整诊断（状态、阶段、原因、建议动作、检查时间、上次成功时间、工具数、下次重试时间）在编辑弹窗顶部。
- **草稿和已保存配置分开展示。** 后台探针只读磁盘，所以在表单里改了地址还没保存时，那一行会带「未保存」标记（含左侧竖条），弹窗里的诊断并列显示两块：「当前表单值」（手动检测的结果）和「已保存的配置」（后台结论）。两者可能不一致，一起显示才不会让人看到一句和刚做的事对不上的话。要确认新值通不通，点「用当前表单值检测」——它只发一次握手，不写任何东西。
- 页面每 15 秒只读一次健康结论；真正的重探由 Host 后台按 TTL 和退避节奏做，页面只是跟上，不会自己另起一套请求节奏。
- 未观测（`状态未知`）和已停用不会套红框，也不会被算进「失败」计数。
- 底部问题按「同一句话 × N」合并展示，最多列 4 类。校验只会挡住真正的问题；凭据、建议一类的东西不在那里出现。
- 「迁移明文凭据」会带上当前表单的值，所以刚填的地址不会在迁移后被回读覆盖；只影响当前作用域，另一个作用域仍以磁盘为准。

**接口**

Host 侧路由都在 `/mcp-settings` 下（`state`、`save`、`validate`、`probe`、`open-project`、`scope/transfer`、`health`、`credentials/migrate`、`snapshots*`、`import`、`export`、`tools*`）。`GET/POST /mcp-settings/servers` 与 `/mcp-settings/health` 保留给旧的单文档调用方（只作用于全局作用域）。

## 安装

装到 web profile（本仓库是独立插件仓库，插件位于根目录）：

```sh
dsh plugin --profile web add github:Tomcat099/dsh-sidebar
```

等价写法（显式 git URL）：

```sh
dsh plugin --profile web add 'git+https://github.com/Tomcat099/dsh-sidebar.git'
```

> **pnpm ≥ 10 首次安装会失败**：git 安装拉的是源码（不是构建产物），pnpm 默认拒绝运行 `prepare` 构建脚本。第一次 `add` 报错时，把 pnpm 打印的确切包键复制进该 profile 的 `pnpm-workspace.yaml`：

```yaml
allowBuilds:
  dsh-sidebar: true
```

> 然后重新执行 `add`。这等于允许该包代码在安装时于你的机器上执行，只对源码可信的包授权；建议锁定 commit：`dsh plugin --profile web add github:Tomcat099/dsh-sidebar#<commit-sha>`，避免后续推送悄悄改变实际运行的内容。

安装后重启 `dsh web`。

本地目录开发（必须带 `file:` 前缀，否则 pnpm 会写成软链）：

```sh
# macOS
dsh plugin --profile web add file:/path/to/dsh-sidebar
# Windows
dsh plugin --profile web add file:C:/path/to/dsh-sidebar
```

改源码先 `npm run build`，再重启 `dsh web`。`file:` 安装是硬链复制：改已有文件会同步，但**新增文件不会被 `pnpm` 搬进 profile**（它会报 `Already up to date`）。加了新文件（例如 `lib/memory/`）之后要清掉 profile 里的旧副本再装一次：

```sh
rm -rf ~/.dsh/profiles/web/node_modules/dsh-sidebar
dsh plugin --profile web add file:/path/to/dsh-sidebar
```

## 开发

```sh
npm install
npm run build     # tsc → lib/（prepare 自包含，git 安装时也会执行）
npm test          # node --test tests/*.test.js
```

`client/client.js`（浏览器 CJS bundle）与 `lib/`（Host 构建产物）随仓库提交，git 安装即可直接用。
